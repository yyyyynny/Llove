# 콜롬비나 음성 생성(TTS) — 창조주 전용 봉인 골격

> 작성: Claude Code 세션 (브랜치 `claude/stoic-newton-bcn8rb`)
> 상태: **봉인 골격 완료** — 서버·끝말잇기 준비 후 플래그만 켜면 연결.

---

## 1. 왜 / 무엇

최고 관리자님이 로컬에서 So-VITS로 학습시킨 **콜롬비나 음성 TTS**(텍스트→3~8초→음성)를
Llove로 가져오기 위한 골격. 원래 목적은 **끝말잇기에서 단어를 그 목소리로 말하기**.

- **RVC 실시간 변조는 제외** (브라우저 불가, 원래도 미흡). TTS만 채택.
- **끝말잇기 게임은 아직 없음** — 다른 세션에서 완성 후 제공 예정. 도착하면
  `음성생성호출(단어)` 한 줄로 연결.

## 2. 올바른 구조 (중요)

```
[Llove(브라우저)]  --텍스트-->  [외부 GPU 서버: 파이썬 So-VITS]  --음성(wav/mp3)-->  [Llove가 재생]
```

- 파이썬 모델은 **외부 GPU 서버에서** 돈다. 브라우저·끝사용자 기기에선 **절대 안 돈다**
  (파이토치+CUDA 필요). Llove는 텍스트를 보내고 **완성된 음성만 받아 재생**한다.
- 서버 위치: 성능 남으면 **본인 PC(RTX4060)+터널(Cloudflare Tunnel 등)**, 아니면
  **유료 클라우드 GPU**. ※ **AWS 프리티어엔 GPU 없음** — 무료 GPU 상시 서버는 사실상 없음.
  Runpod/Vast.ai가 AWS보다 저렴.
- 비밀키는 프론트·레포에 두지 않음 — 서버 또는 Cloudflare Worker에서만 관리(Grok과 동일).

## 3. 이번에 구현된 것 (index.html, 봉인 상태)

Grok 봉인 패턴(`GROK_활성화`)을 그대로 복제.

| 요소 | 이름 | 설명 |
|---|---|---|
| 봉인 플래그 | `const 음성생성_활성화 = false` | ⚠️ 승인 없이 true 금지. 서버 준비 후에만. |
| 호출 함수 | `음성생성호출(텍스트)` | 봉인/미설정 시 fetch 없이 `null`. 활성 시 POST→음성 Blob. |
| 재생 | `음성재생(소스)` | `new Audio()` (프로젝트 최초 오디오 재생 인프라). Blob/URL 모두 허용. |
| 로딩 UI | `음성생성_로딩(켜기)` | "🎙 음성 생성 중…" — **회전 금지 규칙 준수**(점 불투명도 펄스, `@keyframes pulse`). |
| 창조주 게이트 | `갱신_음성설정_UI()` / `음성설정_탭()` | 설정 화면 `#음성설정Row` — 창조주만 노출. 비창조주는 행 숨김+안내 모달. |
| 테스트 벤치 | `#음성생성Bg` 모달, `음성_테스트생성()` | 엔드포인트 입력 + 문장 입력 + [생성·재생]. 봉인 중엔 안내만. |
| 엔드포인트 영속 | `음성엔드포인트_저장/지우기` | `plx_음성엔드포인트`(localStorage) + Firestore `음성엔드포인트`. **코드에 주소 비저장.** |

- 신규 사용자 기본값 `음성엔드포인트: ''`, `사용자데이터_적용`·초기 로드에서 복원.
- `.gitignore`에 모델·음성 파일 커밋 차단 가드 추가(`*.pth`/`*.onnx`/`*.wav`/`/models/` 등).

## 4. 나중에 할 일 (인프라 의존 — 이번 범위 밖)

1. 파이썬 So-VITS 추론을 작은 HTTP API로 감싸기(FastAPI/Flask): `POST {텍스트}` → wav/mp3.
2. 서버를 로컬 터널 또는 클라우드 GPU에 띄우고, **창조주가 설정 패널에 그 주소 입력**.
3. (권장) CORS·토큰 숨김 위해 Cloudflare Worker로 프록시(Grok Worker처럼).
4. 서버 검증 끝나면 **최고 관리자님 승인 후** `음성생성_활성화 = true`.
5. 끝말잇기 게임 도착 시 단어 출제부에서 `음성재생(await 음성생성호출(단어))` 연결.
   → **wchain Phase 6에서 배선 완료.** `wchain/js/음성.js`(독립 게이트, 기본 false) +
   `wchain/js/서바이벌.js`의 AI 단어 출제부에 정확히 이 문구대로 연결됨. 자세한 내용은
   `wchain/시스템.md` "게이트 정책"·"Phase 6" 항목 참조. 이 문서(§3)의 골격 자체는 Llove
   쪽 `js/grok.js`의 `음성생성_활성화`를 그대로 가리키며, wchain 쪽은 별도 독립 변수다.

## 5. 저작권/안전 전제

콜롬비나 = 호요버스 캐릭터 + 성우 목소리. **공개 배포 위험.**
**창조주 전용·비공개·모델 레포 미포함**이 전제. 코드/주석에 상업·공개 배포 표현 금지.

## 7. 밖에서 내 PC를 서버로 쓰기 — 비전문가용 운영 가이드

> 최고 관리자님과 논의해 정한 **실제 운영 방식**. 도메인·인프라 지식 없이도 따라 할 수 있게 정리.
> 핵심: **24시간 켜놓지 않고도, 밖에서도, 공짜로** 본인 PC를 음성 서버로 쓴다.

### 7-1. 어떤 기기로? — 본인 RTX4060 PC가 1순위
- 최고 관리자님 PC에는 **NVIDIA 그래픽카드(RTX4060)** + **So-VITS·콜롬비나 모델이 이미 설치**돼 있다.
  → 가장 빠르고(CUDA) 공짜다. **Colab은 "PC를 못 켜는 상황(밖에서 폰만)"의 대안**일 뿐.
- 왜 Colab이 1순위가 아닌가: Colab은 원래 *GPU 없는 사람용*이다. 최고 관리자님은 GPU가 있고,
  Colab은 껐다 켤 때마다 모델 재업로드·So-VITS 재설치가 필요해 오히려 번거롭다.

| 기기 | PyTorch가 쓰는 것 | 속도 | 비고 |
|---|---|---|---|
| **RTX4060 PC** | NVIDIA GPU(CUDA) | 빠름 | **1순위**, 모델 이미 있음 |
| Colab(무료) | NVIDIA GPU(CUDA) | 빠름 | PC 못 켤 때 대안, 매번 재세팅 |
| 안 쓰는 노트북/폰 | **CPU**(내장그래픽·NPU 못 씀) | 느림 | 캐싱(7-5) 쓰면 가능 |

### 7-2. 밖에서 PC 깨우기 (24시간 안 켜놔도 됨)
- **IoT 물리버튼**(스위치봇류 로봇 손가락)이 전원 버튼을 눌러 켠다. **또는**
- **Wake-on-LAN(WOL)** — 폰 앱으로 "마법 패킷"을 보내 켠다(로봇 손가락 불필요, 공짜, 메인보드 대부분 지원).
- 💡 **밖에서** 깨우는 거라면 WOL은 공유기 설정이 필요해, **IoT 버튼이 오히려 더 쉬울 수 있다**(클라우드 경유).

### 7-3. 서버 자동 실행 + 원격데스크톱(백업)
- 음성 서버 + 터널을 **부팅 시 자동 실행**으로 걸어두면, PC를 깨우는 순간 알아서 돈다
  → **평소엔 Chrome 원격데스크톱을 누를 필요도 없다**.
- **Chrome 원격데스크톱**은 "뭔가 고장났을 때 들어가 손보는 **백업용**"으로만 둔다.

### 7-4. 주소 고정 — ngrok 무료 고정주소 (도메인 지식 0)
- 터널의 랜덤 주소가 껐다 켤 때마다 바뀌는 문제는 **ngrok 무료 고정주소 1개**로 해결한다.
- **도메인 구매·DNS 설정 전혀 불필요.** ngrok 무료 가입 → 주소 이름 한 번 정함
  (예: `colombina-xxxx.ngrok-free.app`) → 그 뒤론 **항상 같은 주소**.
- 비유: *이사 안 가는 집 주소 하나*를 공짜로 받는 것. 설정 패널 입력칸에 **딱 한 번** 넣으면 끝.

### 7-5. 보안 = "비밀번호(비밀키)" — ⚠️ AI 토큰 아님
- 서버를 인터넷에 열기 때문에, 주소를 우연히 아는 사람을 막을 **비밀번호**가 필요하다.
  - **주소** = 집 주소(누구나 알 수 있음) / **비밀키** = 현관 열쇠(창조주만 가짐).
  - 주소를 알아도 비밀키 없으면 못 들어온다. Llove가 음성 요청 시 이 키를 함께 보낸다.
- ⚠️ **용어 주의**: 여기서 말하는 "비밀키"는 **Llove의 AI 대화 토큰(글자 단위·차감)과 전혀 무관**하고,
  **돈과도 무관**하다. 그냥 창조주가 지어내는 비번 한 줄(예: `kolombina1234`).
  혼동 방지를 위해 이 문서·UI에선 **"비밀키/비밀번호"**로 부르고 "토큰"이라 하지 않는다.
- 키는 **프론트·레포에 하드코딩 금지** — 서버 또는 Cloudflare Worker에서만 관리(Grok과 동일 원칙).

### 7-6. 느린 기기 대비 — 단어 미리 캐싱
- 혹시 비NVIDIA 기기(노트북·폰=CPU)를 서버로 쓰면 생성이 느리다. 그러나 **끝말잇기는 단어가
  정해져 있으므로**, 단어들을 **미리 음성으로 만들어 저장(캐싱)** → 게임 땐 즉시 재생하면 된다.
  (생성은 한가할 때 미리, 재생은 즉시) 약한 상시 기기와 궁합이 좋다.

### 7-7. 무료 GPU의 현실
- **Colab·Kaggle = 잠깐용**: 세션이 몇 시간 뒤 자동 종료되고, 약관상 "앱 백엔드 상시 서버"로는 부적합.
- **무료 상시 공개 서버는 사실상 없다**(AWS 프리티어에도 GPU 없음). 단, **개인 테스트**엔 Colab+터널이면 충분.

### 7-8. 최종 흐름 (밖에서)
> 끝말잇기 하고 싶다 → 폰으로 **PC 깨우기**(IoT/WOL) → 부팅되며 **음성서버+터널 자동 실행**
> → Llove 설정의 고정주소로 콜롬비나 음성 재생 → 다 놀면 **다시 잠재우기**.

- **빠르고(RTX4060) · 공짜고(내 PC) · 밖에서도 됨 · 24시간 안 켜놔도 됨.**
- 주의: 집 **정전·인터넷 끊김** 시 그동안은 불가(개인용이라 감수). 보안키는 7-5대로 필수.

### 부록: GPU/CUDA/NPU 한 줄 배경
- **CUDA** = NVIDIA 독점이지만 먼저 깔고 라이브러리(cuDNN 등)를 쌓아 **사실상 표준**이 됨. NVIDIA 카드에서만 돈다.
- **AMD = ROCm**, **인텔 = oneAPI/OpenVINO**, **공용 = OpenCL/DirectML** — 대안은 있으나 CUDA만큼 빠르고 자료 많지 않다.
- **NPU**(폰·최신 노트북)는 회사마다 제각각이라, PyTorch 모델을 NPU용으로 바꾸는 건 "기기별 이식(포팅)"이라 어렵다.
- 결론: 속 편한 길은 **NVIDIA(RTX4060 또는 Colab)**.
