# '잇는' 단어 적절성 판정 Worker

> 2026-08-22 재작성 — 아직 배포 전(봉인 골격). 실제 배포·검증 시 이 파일에 결과를 이어서 기록할 것
> (`wchain/worker/README.md`의 실측 기록 컨벤션과 동일하게 유지).
>
> ⚠️ wchain(끝말잇기)의 기본 판정 체계는 우리말샘 API 하나다. 이 Worker는 그 위에 **새로 얹는**
> 기능이지, 기존 설계를 바꾸는 게 아니다. 파일명을 특정 AI사가 아니라 기능(단어 적절성 판정)으로
> 붙인 것도 그래서다 — 어떤 모델을 붙이든 이름이 그 사실에 좌우되지 않게.

## 이게 뭔가

`wchain/worker/우리말샘-worker.mjs`(사전 존재 검증)와는 **다른 질문**에 답한다 — "사전엔 있지만,
지금 이 판에서 쓰기엔 부당한 단어인가?"(희귀 전문용어·옛말·지명·인명류 등, 후보 필터가 못 거른
경계 케이스). 국립국어원 우리말샘은 학예사가 반복 검수하는 데이터라 "존재하는가"는 신뢰할 만하고,
그래서 존재 검증만으로 잡을 수 있는 오류는 흔치 않다.

- "뜻 보기" 버튼 — 우리말샘 조회 재사용, 사실 확인 + 학습 (AI 불필요)
- "적절성" 버튼(이 Worker) — 맥락상 온당한지 AI 판단

## 왜 교차검증인가

1차 판정에 사용자가 자유 대화로 반박하게 두면 "같은 모델과 같은 대화 안에서 계속 우기기"가 되어
아첨·탈옥에 뚫린다(여러 연구가 "후속 반박이 오면 판정이 뒤집힌다"를 공통 보고). 이 게임은 AI를
설득해 이기는 구조라 일부러 탈옥을 시도할 유인까지 크다. 그래서:

1. **선택지 기반 1회 반박** (자유 대화 아님)
2. **단발 호출** — 대화 맥락을 안 쌓아 압박이 성립하지 않게
3. **다른 회사 모델로 교차검증** — 두 제공사가 편향을 공유하지 않게

### ⚠️ 정직한 한계
위 조치는 프롬프트 인젝션을 *막지* 못한다. 최악의 경우 **"플레이어가 조작해 AI 단어를 판당 최대
5번(이의 예산 상한) 부당하게 취소시킬 수 있다"**까지가 피해 상한이다. 싱글플레이라 남에게 피해가
가지 않고, 취소가 곧 승리도 아니라(AI가 다른 단어를 다시 냄) 이 수준은 감수한다.
**진짜 방어선은 프롬프트 문구가 아니라 코드가 강제하는 경계**다:

| 경계 | 어디서 강제하나 |
|---|---|
| 한 단어당 반박 1회 | `gs.반박한단어` (`wchain/js/서바이벌.js`) |
| 판당 이의 5회 | `gs.dispute_attempts` / `이의_최대횟수` (반박은 추가 차감 없음) |
| 자유 텍스트 100자 | 클라이언트·Worker **양쪽**에서 자름(클라 제한만 믿지 않음) |

## 계약

```
요청  POST { 단어: "가마솥", 맥락: "직전 글자(선택)" }
  → 1차 판정.  응답 { 적절: true|false, 이유: "한 줄 설명" }

요청  POST { 단어, 맥락,
            반박사유: "희귀전문어"|"옛말"|"고유명사"|"방언"|"기타",
            반박보충: "자유 텍스트(기타일 때만, 100자 이내)" }
  → 2차 교차검증(다른 제공사).  응답 형태는 1차와 동일 { 적절, 이유 }
```

2차 응답을 1차와 같은 형태로 둔 이유: 클라이언트가 판정 뒤 처리(`AI단어_취소_재출제()`)를 한
경로로 재사용하기 위함. 실패(4xx/5xx)면 클라이언트는 null로 강등해 "검증 불가" 안내만 띄운다 —
이 Worker가 죽어도 게임이 멈추면 안 된다.

⚠️ `반박사유` 코드는 `wchain/js/적절성판정.js`의 `반박_사유목록`과 **1:1로 일치해야 한다**
(어긋나면 Worker가 400을 돌려줘 반박이 통째로 죽는다). `tests/test-worker-적절성판정.cjs`가
두 파일을 대조해 고정하고 있다.

## 제공사 교체 (모델 미확정 상태)

2026-08-22 조사에서 후보 모델이 계속 뒤집혔다 — `grok-4-fast`는 2026-05-15 단종(내부적으로 더
비싼 grok-4.3으로 리다이렉트 과금), Gemini 2.5 Flash-Lite는 2026-10-16 셧다운 예정, grok-4.5는
추론을 끌 수 없어 단순 판정엔 과비용. 그래서 **교체를 전제로** 어댑터를 뒀다.

세 회사의 HTTP 계약이 실제로 다르다:

| 제공사 키 | 인증 헤더 | 시스템 프롬프트 위치 | 응답 텍스트 경로 | 시크릿 이름 |
|---|---|---|---|---|
| `openai호환` (OpenAI·xAI) | `Authorization: Bearer` | `messages[0]` role:system | `choices[0].message.content` | `OPENAI_API_KEY` |
| `anthropic` | `x-api-key` + `anthropic-version` | top-level `system` | `content[0].text` | `ANTHROPIC_API_KEY` |
| `google` | `x-goog-api-key` | `systemInstruction` | `candidates[0].content.parts[0].text` | `GOOGLE_API_KEY` |

**바꾸려면 `단어적절성판정-worker.mjs`의 이 두 줄만 고치면 된다:**

```js
const 일차_설정 = null;   // 예: { 제공사:'anthropic',  모델:'claude-haiku-4-5' }
const 이차_설정 = null;   // 예: { 제공사:'openai호환', 모델:'gpt-5-nano', 추론:'low' }
```

- 2차는 1차와 **다른 제공사**여야 교차검증 의미가 있다(같은 회사면 편향을 공유).
- 둘 중 하나라도 `null`이면 진입점이 500을 돌려준다 — 실수로 배포해도 조용히 이상하게 동작하지
  않게 한 가드.
- `추론`은 OpenAI 호환만 쓴다(`reasoning_effort`). 미지정이면 아예 안 보낸다.

## 배포 방법 (모델·키 확보 후)

1. 위 두 상수를 채운다.
2. Cloudflare 대시보드에서 새 Worker 생성 (이름은 `wrangler.단어적절성판정.toml.example` 참조 —
   이 폴더의 우리말샘 Worker용 `wrangler.toml.example`과는 다른 파일이니 혼동 주의).
3. `단어적절성판정-worker.mjs` 내용을 그대로 붙여넣고 Deploy.
4. Worker 설정 > Variables and Secrets에서 **고른 제공사의 키**를 등록(위 표의 시크릿 이름).
   1차·2차가 다른 회사면 키도 2개.
5. curl 검증:
   ```bash
   # 1차 판정
   curl -s -X POST 'https://<배포된 주소>/' \
     -H 'Content-Type: application/json' \
     -H 'Origin: https://yyyyynny.github.io' \
     -d '{"단어":"가마솥"}'

   # 2차 교차검증(반박)
   curl -s -X POST 'https://<배포된 주소>/' \
     -H 'Content-Type: application/json' \
     -H 'Origin: https://yyyyynny.github.io' \
     -d '{"단어":"가마솥","반박사유":"방언"}'
   ```
6. 클라이언트 연결: `wchain/js/적절성판정.js`의 `적절성검증_WORKERS_ENDPOINT`(빈 문자열)에 배포
   주소를 채운다.
7. **최고 관리자님 승인 하에** 같은 파일의 `적절성검증_활성화 = true`.
   ⚠️ `scripts/check-deploy.mjs`가 이 플래그가 `false`인지 검사하므로, 켜면 CI가 실패한다 —
   의도적으로 켤 때는 그 검사도 함께 손봐야 한다(승인 없이 조용히 켜지는 걸 막는 장치).

## 배포 후 반드시 실측할 것

이 Worker는 **실제 AI 응답 품질이 전혀 검증되지 않았다**(배포 전이라 불가능). 배포 직후:

- 실제 게임 단어 표본으로 판정이 말이 되는지 (특히 애매한 경계 케이스)
- JSON 파싱 성공률 — 실패하면 관대 쪽(`적절:true`)으로 폴백하므로 조용히 무력해질 수 있다
- 토큰 사용량 실측 → `추론` 강도가 과한지/부족한지 판단
