# '잇는' 그록 단어 적절성 판정 Worker

> 2026-08-22 신설 — 아직 배포 전(봉인 골격 단계). 실제 배포·검증 시 이 파일에 결과를 이어서 기록할 것
> (`wchain/worker/README.md`의 실측 기록 컨벤션과 동일하게 유지).

## 이게 뭔가

"이의있음" 버튼은 지금 `wchain/worker/우리말샘-worker.mjs`(사전 존재 검증)만으로 동작한다.
국립국어원 우리말샘은 학예사가 반복 검수하는 데이터라 "사전 자체가 틀렸다"를 의심할 이유는
거의 없고, 그래서 존재 검증만으로 잡을 수 있는 오류는 흔치 않다.

이 Worker는 **다른 질문**에 답한다 — "사전엔 있지만, 지금 이 판에서 쓰기엔 부당하다고
느껴지는 단어인가?"(희귀 전문용어·옛말·지명·인명류 등, 후보 필터가 못 거른 경계 케이스).
즉 우리말샘 Worker(사실 확인)와 역할이 겹치지 않는 **맥락 판단** 담당이다.

- "뜻 보기" 버튼(예정, 우리말샘 조회 재사용) — 사실 확인 + 학습
- "그록 검증" 버튼(이 Worker) — 맥락상 온당한지 AI 판단

## 게이트 정책

이 Worker 파일 자체엔 on/off 플래그가 없다(우리말샘 Worker와 동일 원칙 — Worker는 상태
없는 프록시). 실호출 여부는 **클라이언트(wchain/js)의 독립 플래그**가 결정해야 한다.
Llove의 `GROK_활성화`(js/grok.js)와는 별개 변수를 wchain 쪽에 새로 두고, 기본값 `false`·
**최고 관리자님 승인 없이 true 금지** 정책을 동일하게 적용할 것. 클라이언트 게이트 배선은
아직 안 돼 있음 — 다음 배치 작업.

xAI 크레딧이 없는 동안은 이 Worker를 배포해도 실호출 시 502(`xAI 호출 실패`)로 떨어진다 —
정상 동작이다. 크레딧 확보 후 `XAI_API_KEY` 시크릿만 등록하면 즉시 살아난다.

## 계약

```
요청  POST { 단어: "가마솥", 맥락: "직전 글자나 상황(선택)" }
응답  { 적절: true|false, 이유: "한 줄 설명" }
```

실패(4xx/5xx)면 클라이언트는 null로 강등해 우리말샘 존재 검증만으로 판정하는 안전망을
타야 한다 — 이 Worker가 죽어도 게임이 멈추면 안 된다.

## 배포 방법 (크레딧 확보 후)

1. Cloudflare 대시보드에서 새 Worker 생성 (이름은 `wrangler.그록판정.toml.example` 참조 —
   Llove의 `xai-api-llove`와 겹치지 않는 별도 이름 사용. 이 폴더의 우리말샘 Worker용
   `wrangler.toml.example`과는 다른 파일이니 혼동 주의).
2. `그록판정-worker.mjs` 내용을 그대로 붙여넣고 Deploy.
3. Worker 설정 > Variables and Secrets에서 `XAI_API_KEY` 등록.
4. 아래로 curl 검증:
   ```bash
   curl -s -X POST 'https://<배포된 주소>/' \
     -H 'Content-Type: application/json' \
     -H 'Origin: https://yyyyynny.github.io' \
     -d '{"단어":"가마솥"}'
   ```
5. 정상 응답 확인되면 `wchain/js`에 클라이언트 게이트 플래그 + 호출 함수 배선 (다음 배치).

## 모델명 확인 필요

`그록_모델 = 'grok-4-fast'`는 2026-08-22 작성 시점 표기다. 실제 배포 전에 xAI 라인업에서
현재 사용 가능한 모델명을 관리자님이 재확인할 것.
