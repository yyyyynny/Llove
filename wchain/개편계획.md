## 1. 지금 '잇는'의 약점 (조사로 확인)

| 영역 | 현재 상태 | 비교 대상이 하는 것 |
|---|---|---|
| 점수 | `score` 필드가 있지만 안 씀. 결과는 버틴 턴·층뿐 | 끄투: 단어 길이·이어진 수·빠르기로 매 턴 점수 |
| 긴장감 | 제한 시간 없음(생각 무한) | 끄투: 턴 시간이 판 진행에 따라 줄어듦 / Bomb Party: 폭탄 타이머가 점점 짧아짐 |
| 뜻 | '📖 뜻 보기' 버튼을 눌러야 AI 단어 뜻만 보임 | 끄투: 받아들여진 단어마다 뜻이 바로 뜸 |
| 연속 보상 | 콤보·스트릭 없음 | 끄투 미션 글자 +50%/회, Duolingo 스트릭 |
| 피드백 | 로그 줄 색 글씨만. 애니메이션은 목숨 흔들림 1개 | 정답 순간 연출, 오답 흔들림, 콤보 배지 |
| 화면 | 로그 텍스트 나열 + 버튼 줄이 빽빽(11px) | 단어 사슬이 시각적 주인공 |
| 결과 | 게임오버 문구 한 줄 | Wordle: 기록·공유 카드 |
| 접근성 | onclick div, 자체 모달 | dialog/details/button (Q13) |

좋은 점(유지): prefers-reduced-motion 전역 처리, `--ease-out` 모션 토큰, 터치 hover 잔류 방지, 페르소나 대사 체계, 난이도표(목숨·힌트·AI 탐욕도).

## 1-2. 끄투 3(kkutu.kr) 실제 화면 관찰 (2026-09-27, 손님 계정 튜토리얼 직접 플레이)

| 요소 | 관찰 | '잇는'에 가져올 점 |
|---|---|---|
| 판(보드) | 가운데 나무 간판에 **이어야 할 글자를 크게**(감). 상대가 입력하면 글자가 한 자씩 타이핑되듯 나타남 | 이을 글자를 화면 주인공으로. AI 단어 타이핑 연출 |
| 턴 타이머 | 간판 아래 노란 바 + 남은 초(14.0초). 라운드 전체 시간(150초)은 차례인 사람 받침대에 표시 | 2-2 타이머의 모양 참고 |
| 미션 | 간판 왼쪽 칩 3개("ㅏ 쓰기 +5", "3글자 낱말 +5", "우리말 쓰기 +5"). 달성하면 칩이 진해지고 **2×** 배지 | 2-4 미션을 조건 칩으로 |
| 뜻 | 받아들여진 단어마다 오른쪽 목록에 카드 쌓임: "#2 자동-차 [명] 뜻풀이…" + "표준국어대사전 – 국립국어원, CC BY-SA 2.0". 이전 카드는 제목만 남고 접힘 | 2-3 뜻 자동 표시와 같은 방식. 출처 표기도 동일하게 |
| 점수 | 캐릭터 받침대 아래 6자리 계기판식 숫자(000060), 1등에게 "선두" 배지, 획득 시 "+3" 떠오름 | 점수 숫자 롤링 + 증가량 떠오름 |
| 입력창 | 내 차례 = 초록 테두리 "내 차례!" / 상대 차례 = "예측"(미리 입력해 두면 +10%) · "힌트"(다른 사람에게 힌트 보내기)로 바뀜 | 차례에 따라 입력창 상태가 바뀌는 것. 예측 입력은 AI전에서도 가능 |
| 스킬 | 입력창 밑 마나 바(80/100) + 스킬 5개(토끼 20·빨대 30·메아리 60·중간말잇기 80·글자 교체 100, Shift+1~5). 정상 턴·미션 달성으로 마나 획득 | 우리 힌트·이의를 '마나 소비 스킬'로 묶는 안 검토 |
| 캐릭터 | 둥근 캐릭터(모레미)가 받침대 위에. 차례인 쪽 받침대가 파랗게 올라옴 | 페르소나(폭군/비서)를 캐릭터로 시각화 |
| 안내 | 튜토리얼 캐릭터가 말풍선으로 한 단계씩 설명, 틀리면 "다시 생각해 보세요!" 토스트 | 첫 플레이 안내 |
| 톤 | 연녹색 체크 배경, 둥근 모서리, 밝고 귀여운 톤 | 우리는 Llove 테마(어두운 고서 등)를 따르므로 **톤은 가져오지 않고 구조만** |

### 커뮤니티 평가 (디시인사이드 끄투 갤러리 '끄투 3 후기')

## 2. 시스템 개편

### 2-1. 점수제 도입 [결정: 넣을지]
끄투 공식(오픈소스 `const.js` getPreScore)을 참고해 **우리 식으로 새로 구현**(끄투 코드는 GPL이라 복사하지 않음, 공식 아이디어만):

```
턴 점수 = 2 × ((5 + 7×글자수)^0.74 + 0.88×이어진단어수) × (0.5 + 0.5×남은시간비율)
```
- 끄투 원형: 긴 단어·판이 길어질수록·빨리 낼수록 점수↑. 같은 단어 재사용은 감점 배율 15/(n+15).
- 타이머를 안 넣으면 `남은시간비율`=1로 두고 길이·연쇄만 반영.
- 난이도 배율(안온 0.8 ~ 심연 1.5)을 곱해 최고 점수를 난이도 간 비교 가능하게.
- 결과 화면·최고 기록(`best`)을 턴 대신 점수로(턴은 보조 표시).

### 2-2. 턴 제한 시간 [결정: 넣을지, 기본 켜기/끄기]
- 끄투: 라운드 남은 시간에 따라 턴 시간 = 15초 − 1.4초×단계(단계 0~10) → 최소 1초.
- Bomb Party: 답할수록 짧아지되 최소 5초.
- **제안**: 설정 토글(기본 끔 — 지금 플레이 감각 보존). 켜면 12초에서 시작, 5턴마다 −1초, 최소 5초. 시간 초과 = 목숨 −1.
- 사전 조회(최대 8초) 대기 시간은 타이머에서 제외해야 함(네트워크 탓에 억울한 패배 방지).

### 2-3. 뜻 자동 표시
- 받아들여진 단어(내 것·AI 것)마다 사슬 카드 밑에 뜻 한 줄을 **나중에 채워 넣기**(카드 먼저 그리고 뜻은 도착하면 표시).
- ⚠️ 비용: 2026-08-22에 매 턴 뜻풀이 조회를 성능 문제로 뺐다. 그래서 **AI 단어는 이미 받은 후보 데이터 재사용**,
  내 단어는 존재 확인 응답에 첫 뜻만 싣는 방식(Worker 응답 필드 1개 추가 → Worker 재배포 필요)을 검토.
- '뜻 보기' 버튼은 자동 표시가 되면 삭제.

### 2-4. 미션 글자 · 콤보
- 미션(끄투): 판마다 제시 글자(가~하) 하나, 그 글자가 들어간 단어면 점수 +50%/개. 달성 시 새 미션.
- 콤보: 연속 정답 3회부터 배지(×3, ×4…), 점수 소폭 가산. 오답·힌트 사용 시 초기화.

### 2-5. 규칙 다듬기 (참고)
- 끄투 3 '매너'는 한방(후속 0개) 금지가 아니라 **후속 단어 10개 미만 공격 단어 금지**로 바뀜 → 우리 한방 규칙의 선택지로 검토.
- 목숨 회복(Bomb Party): 미션 3회 달성 시 목숨 +1 같은 회복 경로.

### 2-6. 결과 · 기록
- 결과 화면: 점수·턴/층·최장 단어·최고 콤보·쓴 단어 사슬 요약.
- 공유 카드(Wordle식, 정답 유출 없는 이모지 요약) — 후순위.
- 멀티플레이·랭킹·상점·캐릭터 꾸미기(끄투)는 **범위 밖**(서버 필요).

## 3. 디자인 개편

원칙(저장소 스킬 frontend-design · animate · emil-design-eng): 시그니처 하나(**단어 사슬**)에 힘을 몰고 나머지는 절제.
자주 일어나는 순간(매 턴)은 짧고 가볍게, 드문 순간(승리·패배·층 클리어)에 연출 예산을 쓴다.

| 화면 | 개편 |
|---|---|
| 플레이 — 로그 | 텍스트 로그 → **단어 사슬 카드**(말풍선형, 이어지는 글자 강조, 뜻 한 줄). 시스템 대사는 작은 줄로 분리 |
| 플레이 — HUD | 점수·목숨·힌트·콤보. 타이머 켜면 상단 바(20% 이하에서 `--warn`→`--err` 색 전환, 깜빡임 없음) |
| 플레이 — 입력 | 이어야 할 글자를 입력창 앞에 크게. 전송 버튼 누르는 즉시 눌림 반응 |
| 버튼 줄 | 11px 촘촘한 3열 → 자주 쓰는 것(힌트·이의)만 노출, 나머지는 '더보기' 시트 |
| 페르소나·모드 선택 | 큰 타이포 + 캐릭터성(폭군/비서) 강조 |
| 결과 | 드문 순간이라 연출 허용: 결과 이모지·점수 카운트업 |
| 모달·접이식 | dialog/details, 클릭 div → button (Q13, 키보드·화면낭독기 지원) |

참고 디자인(awesome-design-md): raycast·linear(어두운 3단 배경 + 단일 강조색 — 우리 `--bg/--card/--elev`와 같은 구조),
nintendo(게임 라벨·배지 문법), nike(결과 화면 타이포 대비). 색은 Llove 테마 5종+커스텀을 그대로 따른다.

## 4. 애니메이션 목록

| 순간 | 효과 | 길이 |
|---|---|---|
| 단어 카드 등장 | 아래→위 살짝 + 투명→선명(`@starting-style`, JS 없이) | 160ms |
| 정답 | 카드 테두리 `--ok` 한 번 번쩍 | 150ms |
| 오답 | 입력창 좌우 흔들림(기존 shakeLR 재사용) | 380ms |
| 목숨 감소 | HUD 흔들림(기존) + 하트 확대→복귀 | 200ms |
| 콤보 3+ | 숫자 배지 톡 튀어나옴 | 120ms |
| 층 클리어·승리·패배 | 결과 연출(드문 순간) | 400~500ms |

모두 `prefers-reduced-motion`이면 끔. `@starting-style`은 구형 안드로이드 웹뷰 지원 **미확인** → 실기기 확인, 미지원이면 애니메이션만 생략.

## 5. 진행 순서 (배치)

1. **결정 받기**: 2-1 점수제 · 2-2 타이머 · 2-3 뜻 자동 표시(Worker 재배포 동반)
2. 시스템 배치: 점수 → 콤보·미션 → 타이머 → 결과 화면 (각각 테스트 추가, 배치마다 커밋)
3. 디자인 배치: 사슬 카드 → HUD·입력 → 버튼 줄 → 선택·결과 화면 → dialog/details
4. 애니메이션 배치 → review-animations 스킬로 점검
5. 실기기(폰) 확인 · 테마 6종 확인 · web-design-guidelines 스킬로 최종 점검
