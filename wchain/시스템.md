## 1. 개요

파이썬 터미널 게임 `K-WordChain · Dark Fantasy Edition v2.2`(원본 2003줄)를 Llove와 연결되는
**웹(JS) 이세계**로 이식한 프로젝트. Llove = "학습 세계", 끝말잇기 = '잇는'(게임 차원, 임시 이름).
같은 사람(구글 계정)이 두 세계를 오간다. 원신의 "같은 여행자, 다른 나라" 구조.

- **배치**: 학습 모드 "밖". Llove 홈(`index.html` `#sh` → `.hh-top`) 우측에 조건부 포탈 아이콘.
- **진입**: 포탈 탭 → 이동 연출 → `wchain/index.html`.
- **로그인**: 같은 GitHub Pages·같은 도메인이라 구글 로그인(Firebase Auth) 자동 공유. 별도 레포·
  별도 Firebase 프로젝트 불필요.

## 3. 해금 — '잇' 회전 퍼즐

포탈은 처음엔 잠겨 있고, **'잇'(끝말잇기의 '잇') 회전 퍼즐**을 풀어야 영구 개방된다.
- '잇' = ㅇ(초성) + ㅣ(중성) + ㅅ(종성). **회전·반전 없는 정방향**을 정답 기준으로 삼는다.
- 조각: **ㅇ → 2조각(좌우 반원)**, **ㅣ → 3조각(세로 3등분)**, **ㅅ → 2조각(두 획 좌/우 대칭)**. 총 7조각.
- 초기엔 각 조각이 90/180/270° 중 무작위로 뒤틀림. 탭/클릭 시 그 조각만 **90° 회전**. 7조각 전부
  0°(정방향)로 맞아 '잇'이 똑바로 읽히면 개방.
- ℹ️ 이 퍼즐의 90° 회전은 **게임 메커니즘의 본질**이다(2026-08-15부터 Llove `CLAUDE.md` 행동
  규칙 8번이 방식을 제한하지 않고 "통일성·불쾌감 없음" 기준으로 바뀌어, 더는 별도 예외가
  아니라 그 기준을 그대로 통과하는 연출이다). Llove 본체 UI는 여전히 fadeUp/slideIn 톤을
  기본으로 쓰되, 필요하면 같은 기준으로 다른 연출도 검토할 수 있다.

- 커밋 케이던스: 약 10구간으로 쪼개 구간마다 커밋·푸시(세션 끊겨도 재개 가능).

⚠️ 이는 2026-07-24의 "API 우선, 실패 시 로컬 폴백" 방침을 한 단계 더 민 것이다. 로컬 사전은
**폴백이 아니라 보조(유행어 칸)** 가 됐다.

### 무엇이 바뀌었나
| | 전 | 후 |
|---|---|---|
| 사전 기준 | 로컬 `DICTIONARY`(280)+`HARD_DICT`(80) | **우리말샘** |
| `data/사전.json` | 없음 | 보조 사전(유행어·줄임말). **현재 비어 있음** |
| `ai_후보사전` | 로컬 기본 + 온라인 추가 | **온라인 기본** + 세션 + 보조 |
| 온라인 조회 | 초월·심연/11층+만 | **전 난이도 항상** |
| 난이도 축 | 로컬(자연스러운 말) vs 온라인(희귀어) | `난이도_슬라이스` — 표제어 순 앞쪽(흔한 말) vs 전체 |
| 원본 360단어 | `js/사전.js`에 하드코딩 | `tests/fixtures/원본사전.cjs` (**파이썬 대조 전용**) |

`난이도_슬라이스`: 우리말샘은 표제어 순으로 오므로 앞쪽이 상대적으로 흔한 말이다.
안온 40% · 격동 70% · 초월·심연 100%(희귀어 포함). 아케이드는 층이 난이도 역할이라 슬라이스 없음.

### 이 전환이 만든 문제와 해결
**① 네트워크가 죽으면 게임이 멈춘다** (로컬 안전망이 사라졌으므로)
- **세션 사전**(`세션_수집어`): 이번 판에서 받은 후보·검증 통과 단어를 누적. 조회가 실패해도
  이미 받아 둔 단어로 AI가 계속 둔다.
- **연속 3회 실패 시 명시적 경고**(`우리말샘_불통인가`): "곧 막힐 수 있다"를 화면에 알린다.
  조용히 이상하게 도는 것보다 낫다.

**② "모르는 것"을 "없는 것"으로 오판** ← 실측으로 발견한 진짜 결함
로컬 사전이 있던 시절에는 후보 풀이 곧 "세상의 모든 단어"라 "풀에 이을 단어가 없다 = 한방"이
성립했다. 이제 풀은 **이번 글자에 대해 받아 온 목록**뿐이라 **다음 글자의 후보는 아직 모른다.**
모르는 걸 "없다"로 단정하면 AI가 내는 정상 단어가 전부 한방으로 오판돼 매 턴 사용자가 이겨 버린다
(테스트에서 실제로 재현됨).
→ `세션_조회글자`에 **실제로 물어본 글자**를 기록하고, `한방_판정가능인가()`로
   **물어본 적 있는 글자에 대해서만** 한방을 판정한다. `safe_filter`·AI 한방 체크·탐욕도 셋 다 적용.
   단, "남는 수가 N개 있다"는 언제나 확실하므로(실제로 세어 봤으니) 불확실한 건 **0일 때뿐**이다 —
   0인데 물어본 적 없을 때만 "모름"으로 뺀다. 이 구분 덕에 난이도 차등이 그대로 유지된다
   (실측: 안온 4.64 > 격동 2.27 > 초월 1.47 > 심연 0.86).

**③ 파이썬 대조의 기준 사전이 사라짐**
대조는 고정 사전이 있어야 성립한다 → 360단어를 `tests/fixtures/원본사전.cjs`로 옮기고
`dictionary_source` 인자로 주입한다. 게임 코드에서는 빠졌지만 **대조 체계는 그대로**다.

### 아케이드 13층 문제 해소
로컬 3글자 단어가 166개뿐이라 AI가 44% 기권하던 문제(10절 "남은 것")는 이 전환으로 사라진다 —
우리말샘에는 3글자 이상 후보가 충분하다.

### 관리자님이 나중에 하실 것
`wchain/data/사전.json`의 `추가단어` 배열에 유행어·줄임말을 넣으면 즉시 인정된다.
`check:deploy`가 형식(문자열·공백 1개 이하)을 검사하고, 테스트가 실제 인정 여부를 확인한다.

## 13. 2026-07-29 (3차) — 실수 폐지 잔여 환산 · 후보 풀 확장 (제보 6 계속)

12장 ②에서 난이도표만 4배로 환산하고 **같은 의미의 상수 셋을 빠뜨렸다.** 실수가 없어진 뒤로
그 값들은 "목숨 = 기회 1회"라는 새 의미로 읽히는데, 옛 숫자가 그대로 남아 아케이드 후반이
설계보다 4배 각박했다.

| 위치 | 종전 | 지금 | 원본 의미 |
|---|---|---|---|
| 아케이드 시작 목숨 | 8(이미 환산) | `아케이드_목숨` = 8 | 목숨 2 × 실수 4 |
| 시련의 탑 생명·어둠의 계약 보상 | **+1** | `목숨보상` = **+4** | 목숨 +1 |
| 14층 무한 등반 진입 | **2** | `아케이드_목숨` = **8** | 목숨 2 |

환산 상수를 `게임상태.js` 한 곳(`실수환산`·`아케이드_목숨`·`목숨보상`)에 모아, 앞으로 값이
다시 흩어지지 않게 했다. 계약 설명 문구와 대사(`시련_응답_2/3`)도 실제 보상에 맞췄다.

### ② 두음법칙 변형 글자를 아예 물어보지 않고 있었다
`온라인후보_가져오기`가 `gs.ai_last_char` **한 글자만** 조회했다. 끝말잇기에서 '락'으로 끝나면
'낙'·'악'으로 시작하는 단어도 규칙상 정답인데, 그 글자들은 후보에서 통째로 빠져 있었다.
게다가 한방 판정(`한방_확정인가`)은 이미 `get_valid_start_chars`로 변형까지 확인하고 있어서
**"AI는 못 찾는데 한방은 아니다"** 라는 어긋난 상태가 만들어졌다.
→ 두 곳 모두 `get_valid_start_chars` 기준으로 통일하고 병렬 조회한다.
부수 효과로 후보 풀이 두세 배 넓어져 12장 ⑤(후보 부족)의 완화책도 된다.
앞말잇기(rev)는 "그 글자로 끝나는 단어"라 변형이 없다 — 종전대로 1회 조회.

또한 `한방_확정인가`가 이미 값을 치르고 받아 온 후보 목록을 판정에만 쓰고 버리고 있었다.
이제 `세션_수집`·`세션_조회글자`에 반영해 안전망과 한방 판정 전제에 함께 쌓인다.

### ③ 빈약한 후보 목록이 기기에 영구히 박히는 문제
후보 캐시 키(`plx_잇는_국어원후보캐시`)에 버전이 없어, 지금 Worker가 주는 2~10개짜리 목록이
**Worker를 고쳐도 그 기기에서는 영원히** 남았다. 키에 `_v2`를 붙이고, 앞으로 Worker가 바뀔 때
숫자를 올리면 옛 캐시가 자연히 무시된다. 추가로 **빈 목록은 캐시하지 않는다** — "이을 단어가
하나도 없다"는 결론은 Worker의 필터·페이지 설정에 좌우되는 값이라 영구 저장할 만큼 확실하지 않다.
게임 데이터 삭제도 목록 대신 `plx_잇는_` 접두사로 쓸어 담아 구버전 키가 남지 않는다.

### ④ 남아 있던 페르소나 대사 2건 (제보 6번 지시의 잔여분)
`react_correct`(정답 반응)·`react_ai_word`(AI 단어 반응)만 배열 리터럴이라 코드에 남아 있었다.

**문구를 늘리려면 JSON에 다음 번호 키만 추가하면 된다** — 코드 수정 불필요.

### ⑥ 12장 ⑤가 문서에만 있고 코드에는 없었다 — 뒤늦게 구현
`912d2ae` 커밋이 **문서 3개만** 담고 있었다. 커밋 메시지와 12장 ⑤가 설명하는 코드 변경

  정말 있는지" 확인해 없으면 미리 알린다. 되돌아왔을 때 판이 바뀌었거나(세대) 이미 다음 턴이면
  버린다. 조회 실패는 말하지 않는다(확인을 못 한 것과 없는 것은 다르다).
- `arcade_restart_floor` — 층 재시작 폐지로 호출부가 사라져 주석으로 봉인, export도 제거.

### ⑦ 힌트·설정에서 마저 나온 것
- `힌트_본체`가 **힌트 잔량을 보기 전에** 온라인 후보를 조회했다. 힌트가 0이면 그 결과를 아예

## 14. 2026-08-15 — Worker 실배포·실측 검증 완료

11~13장에서 클라이언트 쪽 완화(정규화·안전망·경고)만 넣고 "근본 해결은 관리자님 몫"으로
남겨뒀던 Cloudflare Worker를 이번에 실제로 새로 짜서 배포까지 마쳤다. `wchain/worker/` 폴더
신설(`우리말샘-worker.mjs`·`README.md`·`wrangler.toml.example`).

### 시행착오 기록 (같은 실수를 반복하지 않기 위해 남김)
1. **`URIMALSAEM_CERTKEY_NO` 누락** — 첫 버전은 `key` 파라미터 하나면 되는 줄 알고 짰다가
   "서버 설정 오류"만 반환했다. 압축 이전 대화 기록(`4d7429ac-...jsonl`)을 뒤져, 예전 세션이
   서브에이전트로 국립국어원 공식 문서 원문을 직접 읽어 `certkey_no`가 별도로 필요함을 이미
   검증해 뒀었다는 걸 확인 — 그 구조로 복원.
2. **시크릿 값 앞뒤 공백** — `URIMALSAEM_KEY` 길이가 33자(정상 32자 16진수)였다. Cloudflare
   Secret 입력 시 공백/줄바꿈이 한 글자 섞여 들어간 것 — 예전 검증 코드는 `.trim()`을 걸어
   뒀는데 이번에 빠뜨렸다가 재발. `다듬기()` 헬퍼로 모든 값 사용 지점에서 trim.
3. **`num=1` 거부** — 단어 존재 확인에 `num=1`을 썼더니 "103 Invalid num value"로 거부됐다
   (후보 조회의 `num=100`은 정상). 예전 코드도 단어 조회엔 `num=20`을 썼지 1을 쓴 적이
   없었다 — API가 num에 최솟값 제약을 두는 것으로 보인다. 20으로 통일.
4. 원인 진단을 위해 `디버그`·`시크릿점검` 임시 진단 경로(실패 상세·시크릿 길이·정/역방향
   실증 테스트)를 코드에 넣어 재배포 왕복을 줄였고, 원인 확정 후 걷어내 최종본을 정리했다.

### 화면 전환을 왜 "들어오는 쪽만" 맞췄나
Llove 는 나가는 화면(`slideOut .25s`)까지 `entering`/`leaving` 클래스와 `setTimeout` 으로
타이밍을 맞추지만, wchain 의 `화면(id)`(`js/서바이벌.js`)은 클래스만 토글하는 **동기 함수**다.
나가는 연출을 넣으려면 그 기계장치를 통째로 들여와야 하는데, 얻는 것보다 회귀 위험이 크다.
그래서 들어오는 쪽만 Llove 실측값(`.35s` · 같은 커브)으로 맞췄다 — 두 세계를 오갈 때
전환 감각이 갈리지 않는 것이 목적이었고 그건 달성된다.
