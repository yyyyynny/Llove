# 잇는 (wchain) — 시스템 문서

> 끝말잇기 게임(임시 이름: '잇는' — 최종 이름 미정, 확정 시 일괄 치환)의 설계·이식·게이트 정책 문서.
> Llove의 `언어_SYSTEM_v5.md`·`CLAUDE.md`에 대응하는 wchain 전용 지침.
> 다음 세션은 이 문서 + 루트 `/root/.claude/plans/sunny-tickling-heron.md`를 먼저 읽고 이어갈 것.
> 최고 관리자: 성재훈 / 최종 업데이트: 2026-07-25 (구 허용 모드 추가)

## 1. 개요

파이썬 터미널 게임 `K-WordChain · Dark Fantasy Edition v2.2`(원본 2003줄)를 Llove와 연결되는
**웹(JS) 이세계**로 이식한 프로젝트. Llove = "학습 세계", 끝말잇기 = '잇는'(게임 차원, 임시 이름).
같은 사람(구글 계정)이 두 세계를 오간다. 원신의 "같은 여행자, 다른 나라" 구조.

- **배치**: 학습 모드 "밖". Llove 홈(`index.html` `#sh` → `.hh-top`) 우측에 조건부 포탈 아이콘.
- **진입**: 포탈 탭 → 이동 연출 → `wchain/index.html`.
- **로그인**: 같은 GitHub Pages·같은 도메인이라 구글 로그인(Firebase Auth) 자동 공유. 별도 레포·
  별도 Firebase 프로젝트 불필요.

## 2. 저장소 구조

```
wchain/
├── index.html      # 진입점 (Phase 1: 준비 중 placeholder)
├── 시스템.md        # 이 문서
└── (추후) js/·style·자동대조 스크립트 등
```
루트 `index.html`(=Llove)·`js/`·`style.css`·`data/`는 그대로 유지. wchain은 이 하위 폴더에만 격리.

## 3. 해금 — '잇' 회전 퍼즐

포탈은 처음엔 잠겨 있고, **'잇'(끝말잇기의 '잇') 회전 퍼즐**을 풀어야 영구 개방된다.
- '잇' = ㅇ(초성) + ㅣ(중성) + ㅅ(종성). **회전·반전 없는 정방향**을 정답 기준으로 삼는다.
- 조각: **ㅇ → 2조각(좌우 반원)**, **ㅣ → 3조각(세로 3등분)**, **ㅅ → 2조각(두 획 좌/우 대칭)**. 총 7조각.
- 초기엔 각 조각이 90/180/270° 중 무작위로 뒤틀림. 탭/클릭 시 그 조각만 **90° 회전**. 7조각 전부
  0°(정방향)로 맞아 '잇'이 똑바로 읽히면 개방.
- ⚠️ **회전 애니메이션 예외**: Llove `CLAUDE.md`의 "회전 완전 금지" UI 규칙은 화면 전환·장식용
  트랜지션을 겨냥한 것. 이 퍼즐의 90° 회전은 **게임 메커니즘의 본질**이라 wchain 한정으로 허용한다
  (관리자님 확정). Llove 본체 UI는 이 예외를 쓰지 않는다.

## 6. 이식 규칙·검증

- **모듈 단위 라운드**로 이식(2000줄 한 번에 X). 파이썬 원본 ↔ JS 이식본에 같은 입력을 넣어 출력
  일치를 스크립트로 **자동 대조**(두음법칙·한방 판정 등 입출력 명확한 함수부터).
- 블로킹 `input()` 루프 → 기존 `game_state` 상태 머신을 살린 **이벤트 기반**으로. `time.sleep` →
  `setTimeout`/async, ANSI 색 → CSS.
- 원본 버그도 옮기며 걸러냄(맹목 복사 금지). 완료 후 **오푸스 1회 재검수**로 로직 누락·오역 0건 확인.
- 커밋 케이던스: 약 10구간으로 쪼개 구간마다 커밋·푸시(세션 끊겨도 재개 가능).

   - `wchain/js/서바이벌.js` `단어_제출`: `존재함 === null`이면 `단어_처리`(→ `user_defeat`로
     이어져 실수가 매겨짐)를 아예 호출하지 않고, "⚠️ 국립국어원 사전 확인에 실패했습니다(네트워크
     문제로 추정). 같은 단어를 다시 입력해 보세요." 안내만 띄우고 그대로 종료 — 실수도 안 매기고
     사용된 단어로도 기록하지 않아 즉시 재시도 가능.
   - `국어원_타임아웃_MS`도 1.5초 → **3초**로 상향(느린 네트워크에서 흔한 단어까지 놓치는 사례
     완화).
   - ⚠️ 이 샌드박스 개발 환경에서는 브라우저의 실네트워크가 Worker까지 아예 도달하지 못해(같은

     환경(GitHub Pages, 일반 사용자 브라우저)에서는 정상적으로 온라인 확인이 될 가능성이 높지만,
     관리자님이 직접 재확인 권장.
   - `.log .line.warn{ color:var(--warn); }` CSS 규칙도 이때 추가(기존에 `로그_추가(..., 'warn')`
     호출은 여러 곳에 있었는데 정작 `.warn` 클래스에 대응하는 색상 규칙이 없어 시각 효과가
     전혀 없던 사소한 기존 결함도 함께 수정).

     갱신) + 신규 `e2e_국어원_실패공정성.mjs` 4/4(fetch 강제 실패 상태에서 "이름" 제출 재현 —

2. **백도어 미작동 — 실제로는 사용법 문제였으나, 관리자님 지시로 슬래시 없이 통일.** 처음엔
   관리자님이 단어 입력창에 `yyyyynny`(슬래시 없이)만 입력해서였음 — wchain 백도어는 원본
   파이썬 그대로 `/yyyyynny`(맨 앞 슬래시 포함)를 정확히 일치시켜야 발동했기 때문(코드 결함은
   아니었음). 다만 Llove 쪽 게스트 로그인 백도어(슬래시 없이 아무 데서나 타이핑)와 형태가 달라
   헷갈리기 쉽다는 지적에 따라, `서바이벌.js` `단어_제출`의 조건을 `raw === 'yyyyynny'`(슬래시
   제거)로 변경해 Llove와 동일한 시퀀스로 통일함. 원본 파이썬과의 문자열 불일치는 웹 UX 통일을
   위한 의도적 변경(다른 실질 규칙과 달리 이 백도어 자체가 원본에 없던 웹 전용 기능이라 원본
   충실성 원칙 대상이 아님).
3. **로그 박스가 기기 크기에 안 맞고 기본 스크롤바가 이질적.** `wchain/index.html` `.log`의
   `max-height:220px` 고정값을 **`min(50dvh, 420px)`**로 바꿔 `flex:1`이 실제로 뷰포트 높이에
   맞춰 늘어나고 줄어들게 함(작은 화면은 `min-height:120px`가 하한을 잡아줌). 기본 브라우저
   스크롤바 대신 `scrollbar-width:thin`(Firefox) + `::-webkit-scrollbar`(Chromium 계열)로 테마
   색(`--bdr`, hover 시 `--acc` 계열)에 맞춘 얇은 커스텀 스크롤바 적용(`.modal-bx`에도 동일 적용).
   - 검증: Playwright로 모바일(390×844)·큰 화면(900×1000)·작은 화면(390×600) 3개 뷰포트에서
     로그를 8줄씩 채워 스크린샷 비교 — 화면 크기에 따라 박스 높이가 달라지고, 스크롤바가 얇고
     테마에 맞게 렌더됨을 육안 확인.
