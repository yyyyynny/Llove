# 잇는 (wchain) — 시스템 문서

> 끝말잇기 게임(임시 이름: '잇는' — 최종 이름 미정, 확정 시 일괄 치환)의 설계·이식·게이트 정책 문서.
> Llove의 `언어_SYSTEM_v5.md`·`CLAUDE.md`에 대응하는 wchain 전용 지침.
> 다음 세션은 이 문서 + 루트 `/root/.claude/plans/sunny-tickling-heron.md`를 먼저 읽고 이어갈 것.
> 최고 관리자: 성재훈 / 최종 업데이트: 2026-07-19 (Phase 1 착수)

## 1. 개요

파이썬 터미널 게임 `K-WordChain · Dark Fantasy Edition v2.2`(원본 2003줄)를 Llove와 연결되는
**웹(JS) 이세계**로 이식한 프로젝트. Llove = "학습 세계", 끝말잇기 = '잇는'(게임 차원, 임시 이름).
같은 사람(구글 계정)이 두 세계를 오간다. 원신의 "같은 여행자, 다른 나라" 구조.

- **배치**: 학습 모드 "밖". Llove 홈(`index.html` `#sh` → `.hh-top`) 우측에 조건부 포탈 아이콘.
- **진입**: 포탈 탭 → 이동 연출 → `wchain/index.html`.
- **로그인**: 같은 GitHub Pages·같은 도메인이라 구글 로그인(Firebase Auth) 자동 공유. 별도 레포·
  별도 Firebase 프로젝트 불필요.

## 2. 저장소 구조

```
wchain/
├── index.html      # 진입점 (Phase 1: 준비 중 placeholder)
```

루트 `index.html`(=Llove)·`js/`·`style.css`·`data/`는 그대로 유지. wchain은 이 하위 폴더에만 격리.

## 3. 해금 — '잇' 회전 퍼즐

포탈은 처음엔 잠겨 있고, **'잇'(끝말잇기의 '잇') 회전 퍼즐**을 풀어야 영구 개방된다.
- '잇' = ㅇ(초성) + ㅣ(중성) + ㅅ(종성). **회전·반전 없는 정방향**을 정답 기준으로 삼는다.
- 조각: **ㅇ → 2조각(좌우 반원)**, **ㅣ → 3조각(세로 3등분)**, **ㅅ → 2조각(두 획 좌/우 대칭)**. 총 7조각.
- 초기엔 각 조각이 90/180/270° 중 무작위로 뒤틀림. 탭/클릭 시 그 조각만 **90° 회전**. 7조각 전부
  0°(정방향)로 맞아 '잇'이 똑바로 읽히면 개방.
- ⚠️ **회전 애니메이션 예외**: Llove `CLAUDE.md`의 "회전 완전 금지" UI 규칙은 화면 전환·장식용
  트랜지션을 겨냥한 것. 이 퍼즐의 90° 회전은 **게임 메커니즘의 본질**이라 wchain 한정으로 허용한다
  (관리자님 확정). Llove 본체 UI는 이 예외를 쓰지 않는다.

## 6. 이식 규칙·검증

- **모듈 단위 라운드**로 이식(2000줄 한 번에 X). 파이썬 원본 ↔ JS 이식본에 같은 입력을 넣어 출력
  일치를 스크립트로 **자동 대조**(두음법칙·한방 판정 등 입출력 명확한 함수부터).
- 블로킹 `input()` 루프 → 기존 `game_state` 상태 머신을 살린 **이벤트 기반**으로. `time.sleep` →
  `setTimeout`/async, ANSI 색 → CSS.
- 원본 버그도 옮기며 걸러냄(맹목 복사 금지). 완료 후 **오푸스 1회 재검수**로 로직 누락·오역 0건 확인.
- 커밋 케이던스: 약 10구간으로 쪼개 구간마다 커밋·푸시(세션 끊겨도 재개 가능).

### 후속 수정 (2026-07-24) — 국어원_활성화 true 전환 + 앞말잇기(rev) 설정 노출
- **`국어원_활성화`(Phase 5 게이트) → true 전환.** 관리자님이 Cloudflare Worker(`urimalsaem-llove`)

- **앞말잇기(`gs.rev`) 설정 토글 신설.** 파이썬 원본 엔진에 있던 기능이 JS 이식 시 `gs.rev`로
  이식됐고 `find_words`/`is_hanbang`도 이미 이 값을 받아 처리하도록 돼 있었으나(Phase 2 대조
  검증 대상), **UI에 켜는 버튼이 없어 실제로는 켤 방법이 없었음**(관리자님이 발견). 서바이벌
  설정 화면(`wchain/index.html` `#s-설정`)에 `#opt-방향` 버튼 신설, `wchain/js/서바이벌.js`의

  두음법칙 동시 ON 시 두음법칙 자동 OFF(원본 규칙)는 기존 `게임_시작()` 로직 그대로 유지.

    함(추후 검토 항목, 지금은 미착수).

### 후속 확장 (2026-07-24) — AI 단어 생성도 국어원 API 우선 사용(하이브리드)
- **배경**: 관리자님이 "AI 후보 생성은 로컬 사전만 쓴다"던 기존 제약을 다시 물었고, 실측으로
  재확인한 결과 **오판이었음이 드러남** — 국어원 오픈API에 "고급 검색"(`advanced=y&target=1&
  method=start|end`)이 있어 "이 글자로 시작/끝나는 단어 목록"을 실제로 돌려준다(기본 검색은
  부분일치라 안 되는 줄 알았던 게 잘못된 판단이었음, `q=가` 실측으로 검증). 관리자님 확정 방침:
  **API 우선, 실패 시에만 로컬 폴백**(완전 제거는 네트워크 장애 시 게임이 막힐 위험이 있어 채택 안 함).
- **Worker 확장(v2)**: 기존 뜻풀이/존재 조회(모드 2, `단어` 필드)에 **후보 목록 조회(모드 1,
  `글자`+`방향` 필드)**를 추가. `method=start`(전방일치)/`end`(후방일치)로 실제 단어만 받고,
  Worker에서 접사·구·복합표기(하이픈·공백·`^` 포함 표기)·1글자 항목을 걸러서 반환한다.
- **wchain/js/국어원.js**: `국어원_후보목록조회(글자, 방향)` 신설 — 게이트 off·엔드포인트 미설정
  ·실패 시 빈 배열(로컬 강등). `plx_잇는_국어원후보캐시`로 (글자,방향) 단위 캐시. **AI 턴마다
  실호출이라 네트워크가 느리면 응답이 멈춘 것처럼 보일 수 있어 1.5초 타임아웃(AbortController)을
  둠** — 넘으면 즉시 포기하고 로컬로 강등, 게임 흐름이 멈추지 않는다.
- **wchain/js/게임규칙.js**: `ai_generate_word(gs, 추가후보=[])`로 2번째 인자 추가 — 기존
  attack_mode/safe_filter 등 검증된 선택 로직은 전혀 손대지 않고, "입력 풀(로컬+온라인 후보)만
  넓히는" 방식이라 회귀 위험이 낮음. `ai_generate_word_비동기(gs)` 신설 — 게이트 켜져 있으면
  온라인 후보를 먼저 받아 병합 후 기존 함수 호출, 꺼져 있으면 즉시 로컬만(회귀 없음).
- **wchain/js/서바이벌.js**: 호출부 2곳(`단어_처리`, `버튼_이의`) 전부 `async`로 전환 +
  `await ai_generate_word_비동기(gs)`로 교체. 둘 다 기존에 fire-and-forget으로만 호출되던
  자리라 async 전환 자체는 회귀 없음.
- **실사용 영향**: 게이트 on 상태에선 AI 턴마다 실제 네트워크 지연이 생길 수 있음(캐시 미스
  시, 최대 1.5초). 캐시가 쌓이면(같은 글자 재등장) 이후엔 즉시 응답. 로딩 표시 UI는 아직
  없음(추후 폴리시 항목).
- 검증: 실브라우저 E2E 서바이벌 26/26(타임아웃 반영해 대기시간 상향) 재통과 — 콘솔에 실제
  네트워크 지연으로 인한 타임아웃 로그가 찍히면서도 게임 진행 자체는 끊기지 않음을 확인.
  전수34·아케이드17도 회귀 없음. Worker v2 실배포·`method=start/end` 실호출 검증은 관리자님이
  Cloudflare에 새 코드 반영 후 진행 예정.
